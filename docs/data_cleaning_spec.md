# 音乐语料库：数据清洗、去重与预处理规范

## 1. 总体目标

工业音乐语料库的清洗分为 **元数据清洗、音频质量过滤、多级去重** 三个层级，目标是移除低质、错误、重复样本，避免模型学习到噪声信息，同时通过标准化预处理确保输入一致性。

---

## 2. 元数据清洗（Metadata Cleaning）

### 2.1 字段标准化

| 字段 | 标准 | 说明 |
|------|------|------|
| 乐器标签 | GM128（General MIDI Level 1） | 统一映射到标准乐器编码 |
| 情绪标签 | VAD（Valence-Arousal-Dominance） | 三维情绪模型 |
| 流派标签 | 三级分类体系 | 一级大类 → 二级子类 → 三级细分 |
| 语言代码 | ISO 639-1 | 如 zh, en, ja |
| 时长 | 秒级浮点数 | 如 180.5 |

### 2.2 错误与缺失修正

- **补全策略**：利用 MusicBrainz / Discogs API 补全缺失的流派、语言、创作者信息
- **冲突消解**：对多源标签冲突，采用 "专家规则 + 预训练模型校验" 双轨制，保留置信度最高的结果
- **无效剔除**：移除元数据严重缺失（关键字段缺失率 > 50%）或无法匹配版权状态的样本

---

## 3. 音频质量清洗流水线（Audio Quality Pipeline）

### 3.1 前置：格式标准化

```
原始音频
  └── 格式标准化 → 统一为 WAV/FLAC，44.1kHz 或 48kHz，16-bit/24-bit
```

| 参数 | 标准 | 说明 |
|------|------|------|
| 容器格式 | WAV / FLAC | 无损归档，禁止 MP3 作为原始存储 |
| 采样率 | 44.1kHz（音乐）/ 48kHz（影视配乐） | 生成类模型要求 ≥ 44.1kHz |
| 位深度 | 16-bit（标注用）/ 24-bit（训练用） | 24-bit 保留更多动态余量 |

### 3.2 基础损坏检测

- **文件完整性**：通过 `ffmpeg -v error` 检测无法解码、头信息损坏的文件
- **静音占比**：整段静音超过 30% 直接剔除
- **时长过滤**：剔除时长 < 5 秒或 > 10 分钟的异常样本（视任务调整）

### 3.3 音质门槛过滤

| 检测项 | 规则 | 工具/指标 |
|--------|------|-----------|
| 采样率 | 剔除 < 16kHz（标注）或 < 22.05kHz（训练） | ffprobe / librosa.get_samplerate |
| 码率 | 剔除 < 128kbps（有损源） | ffprobe |
| 信噪比（SNR） | < 15dB 标记为低质量，< 10dB 剔除 | librosa.effects.split + 能量阈值 |
| 削波/过载检测 | 波形顶底削波（>0.5% 样本触及 0dBFS） | essentia.AudioLoader + 峰值检测 |
| 动态范围 | 排除 DR < 4 的严重压缩素材 | ffmpeg loudnorm 或 pydub |
| 底噪频谱 | 底噪门限检测，异常持续噪声标记 | 频谱平坦度分析 |

### 3.4 内容过滤

| 检测项 | 规则 | 方法 |
|--------|------|------|
| 静音段 | >30% 静音则剔除 | librosa.effects.split |
| 非音乐内容 | 纯语音、环境音、广告片段 | 音频事件检测模型（如 YAMNet / PANNs） |
| 人声成分 | 视任务决定是否保留纯器乐 | demucs 人声分离后检测人声 stem 能量占比 |
| 内容安全 | 敏感言论、违法内容 | 音频内容识别模型 + 关键词 ASR 后过滤 |

### 3.5 响度与动态校验

- **响度归一化**：按 ITU-R BS.1770-4 标准，目标 -14 LUFS（参考值，可据任务调整）
- **动态范围评估**：排除严重过载、响度异常的现场录音或盗版转录素材
- **True Peak 限制**：确保 True Peak < -1.0 dBTP，防止后续处理产生削波

## 4. 多级去重机制（Deduplication）

音乐去重不仅针对完全相同的文件，还需覆盖同一作品的不同版本、剪辑版、翻唱版。

### 4.1 精确去重（Exact Deduplication）

- **方法**：文件级 MD5 / SHA-256 哈希比对
- **策略**：哈希值完全一致时，保留文件体积最大或元数据最完整的版本，其余剔除

### 4.2 近似去重（Approximate Deduplication）

- **方法**：采用 Chromaprint（fpcalc）/ AcoustID 提取声学指纹，计算余弦相似度
- **阈值**：相似度 > 0.9 判定为重复，保留音质评分最高的版本
- **评估**：可用轮廓系数（Silhouette Score）评估聚类质量

### 4.3 片段级去重（Segment-level Deduplication）

- **方法**：将长音频按 5–30 秒滑动窗口切片（重叠 50%），逐段提取指纹比对
- **目的**：避免同一首歌的不同节选片段在数据集中重复出现

### 4.4 跨集去重与泄露防控（Leakage Prevention）

- **原则**：严格执行 训练 / 验证 / 测试集跨集去重
- **方法**：在去重阶段建立全局指纹库，确保同一作品（含不同版本、remix、翻唱）只出现在单一数据子集中
- **翻唱识别**：对高相似度但非完全重复的版本（如翻唱），通过 MAESTRO-BERT 768 维风格嵌入 + K-Means/DBSCAN 聚类识别，按任务需求决定是否视为重复

---

## 5. 辅助清洗技术

| 技术 | 方法 | 工具/指标 |
|------|------|-----------|
| 风格一致性 | 提取 768 维风格嵌入，L2 归一化后聚类，剔除异常离群点 | MAESTRO-BERT 嵌入 + K-Means/DBSCAN |
| 语言过滤 | fastText / CLE 语言识别 API | 阈值 0.9，确保歌词/描述语言纯度 |
| PII 移除 | 正则匹配手机号、身份证、邮箱 | 规则 + NER 模型联合检测 |

---

## 6. 音频预处理标准（Preprocessing）

清洗后的音频进入预处理阶段，输出模型可用的标准格式。

| 处理步骤 | 标准参数 | 说明 |
|----------|----------|------|
| 重采样 | 目标 44.1kHz 或 48kHz | 与模型输入对齐；使用 soxr 高质量重采样 |
| 声道处理 | 立体声保留；单声道需显式标记 | 部分模型（如 CLAP）需单声道输入 |
| 分块（Chunking） | 5–30 秒片段，滑动窗口重叠 50% | 长音频切分，避免截断音乐结构 |
| 响度归一化 | ITU-R BS.1770-4，目标 -14 LUFS | 避免响度偏差影响训练；使用 pyloudnorm |
| 特征提取（可选） | 梅尔频谱图（Mel-spectrogram）、CQT、Chroma | 作为模型前端输入，按需预计算缓存 |

## 7. 流水线总览

```
原始音频
  ├── [Stage 1] 元数据清洗
  │     ├── 字段标准化（GM128 / VAD / 三级流派）
  │     ├── 缺失补全 & 冲突消解
  │     └── 无效样本剔除
  ├── [Stage 2] 格式标准化
  │     └── WAV/FLAC, 44.1kHz/48kHz, 16/24-bit
  ├── [Stage 3] 音频质量清洗
  │     ├── 损坏检测 & 静音过滤
  │     ├── 音质门槛（采样率/SNR/削波/动态范围）
  │     ├── 内容过滤（非音乐/人声/安全）
  │     └── 响度归一化（-14 LUFS）
  ├── [Stage 4] 多级去重
  │     ├── 精确去重（MD5/SHA-256）
  │     ├── 近似去重（Chromaprint, 余弦相似度 > 0.9）
  │     ├── 片段级去重（滑动窗口切片）
  │     └── 跨集泄露防控
  ├── [Stage 5] 辅助清洗
  │     ├── 风格一致性聚类
  │     ├── 语言过滤
  │     └── PII 移除
  └── [Stage 6] 预处理输出
        ├── 重采样 & 声道处理
        ├── 分块（5-30s, 50% 重叠）
        └── 特征提取（Mel/CQT/Chroma）
```

## 8. 与本项目的运行环境拆分

基于现有环境（Mac 本地 + GPU 远程 + OSS 存储），流水线按运行环境拆分：

| 阶段 | 运行环境 | 说明 |
|------|----------|------|
| Stage 1–2（元数据 + 格式标准化） | GPU / 远程 | 批量处理，上传 OSS |
| Stage 3（质量清洗） | GPU / 远程 | 重计算任务，产出清洗日志 CSV |
| Stage 4–5（去重 + 辅助清洗） | GPU / 远程 | 全局指纹库构建，产出去重映射表 |
| Stage 6（预处理） | GPU / 远程 | 按模型需求切分、提取特征，上传 OSS |
| 人工校验 | Mac 本地 | 通过 Label Studio 读取本地音频，标注后回传元数据 |

### 核心约束

1. **OSS 纯备份**：业务绝不从 OSS 读取音频，OSS 仅作备份归档
2. **本地磁盘为唯一业务数据源**：所有业务读取本地磁盘
3. **GPU↔Mac 通过 rsync 直传**：不走 OSS 中转
4. **raw_audio 只读**：入库后永不修改、永不删除
