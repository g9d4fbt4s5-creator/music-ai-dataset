## 四、时间预算

### 完整流水线跑一遍（500首）

| Stage | 任务 | 预估耗时 | 并行度 |
|-------|------|---------|--------|
| **Stage 0** | 采集+下载 | 2-4小时 | 多线程下载 |
| **Stage 0.5** | 清洗+去重 | 0.5小时 | 批量处理 |
| **Stage 1** | 质量检查（librosa） | 0.5小时 | CPU并行 |
| **Stage 2** | YAMNet 推理 | 0.3小时 | GPU加速 |
| **Stage 3** | QC Gate 判定 | 0.1小时 | CPU |
| **Stage 4** | 近似去重（Chromaprint） | 0.5小时 | CPU并行 |
| **Stage 5.1** | MERT 嵌入提取 | 2小时 | GPU |
| **Stage 5.2** | CLAP 嵌入提取 | 1.4小时 | GPU |
| **Stage 5.3** | DBSCAN 聚类 | 0.2小时 | CPU |
| **L1** | 物理特征计算 | 0.5小时 | CPU并行 |
| **L2** | 语义标签（分类器） | 0.5小时 | GPU |
| **L3** | 结构分段（DeepSeek） | 1小时 | API调用（受速率限制） |
| **L4** | KNN传播+Caption | 1小时 | CPU+API |
| **Stage 6** | 乐段切片 | 0.5小时 | CPU并行 |
| **HITL** | 人工听检（marginal样本） | 2-4小时 | 人工（异步，不阻塞流水线） |
| **合计（自动部分）** | — | **~11-13小时** | — |
| **合计（含人工）** | — | **~13-17小时** | — |

### 关键路径

```
采集(2-4h) → 清洗(0.5h) → 质检(0.5h) → YAMNet(0.3h) → QC(0.1h)
→ 去重(0.5h) → 嵌入提取(3.4h, MERT+CLAP可并行) → 聚类(0.2h)
→ L1-L4预标注(3h, 部分可并行) → 切片(0.5h)
→ 人工听检(2-4h, 异步)
```

**最短路径（嵌入并行+预标注并行）**：约 8-10 小时
**串行执行**：约 13-17 小时

## 六、风险与缓冲

| 风险 | 概率 | 影响 | 缓冲措施 |
|------|------|------|---------|
| **磁盘空间不足** | 中 | 高 | 预留100GB（3倍于预估32GB） |
| **GPU 节点排队** | 高 | 中 | 选择闲时运行，或提前预约 |
| **API 速率限制** | 中 | 中 | L3/L4 分批调用，加重试机制 |
| **API 欠费/中断** | 低 | 高 | 预存¥50，设置余额告警 |
| **Demucs 分轨耗时超预期** | 中 | 中 | 如不需要分轨可跳过，节省4小时 |
| **人工听检耗时超预期** | 中 | 中 | marginal 率控制在 15% 以内 |
| **数据质量问题（损坏/重复）** | 中 | 中 | Stage 0.5 严格清洗，预留10%重跑时间 |

### 总缓冲建议

| 项目 | 预估值 | 建议预留（1.5倍缓冲） |
|------|--------|---------------------|
| 存储 | 32 GB | **100 GB** |
| GPU | 4-8 GPU-hours | **12 GPU-hours** |
| API 费用 | ¥15-25 | **¥50** |
| 时间（自动） | 11-13小时 | **20小时** |
| 人力 | 6-11小时 | **15小时** |

## 七、500首 vs 27首对比

| 维度 | 27首（当前） | 500首（目标） | 放大倍数 |
|------|------------|-------------|---------|
| 存储 | ~2 GB | ~32 GB | 16x |
| GPU 时间 | ~0.2 GPU-hours | ~4-8 GPU-hours | 20-40x |
| API 费用 | ~¥1-2 | ~¥15-25 | 15x |
| 自动流水线时间 | ~1小时 | ~11-13小时 | 11-13x |
| 人工听检 | ~1小时（9首） | ~2-4小时（50-100首） | 2-4x |
| marginal 样本数 | 3首 | ~50-100首 | 17-33x |
| fail 样本数 | 6首 | ~50-100首 | 8-17x |

**关键洞察**：500首不是27首的简单线性放大，marginal/fail 样本的绝对数量会大幅增加，
人工听检和 badcase 分析的工作量会显著上升。HITL 异步闭环和 badcase 自动收集机制
在500首规模下变得至关重要。
